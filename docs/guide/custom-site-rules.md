# 自定义网站适配

某个网站漏译正文，或把作者信息、导航一起翻译时，可以添加一份 JSON 规则，告诉 FluentRead 正文在哪里。规则会同时用于悬浮翻译和全文翻译。

入口是 **设置 → 网站规则 → 网站适配**。一般从复制该网站的内置规则开始；找不到内置规则时，再添加自己的规则。

## 从复制内置规则开始

1. 确认 **启用网站适配** 已打开，展开 **查看内置规则**。
2. 在 **搜索网站** 中输入名称或域名，点击找到的网站名称。
3. 点击 **复制到自定义草稿**。这会把规则加入下方 **JSON 编辑草稿**；需要的模板内容会一并展开。
4. 在草稿里修改正文或保护区域的选择器，保留原来的 `id`，然后点击 **保存规则**。
5. 等待保存成功提示，回到网页重新触发翻译，检查修改后的范围。

**相同 `id` 的自定义规则会完整替换内置规则。** 因此，修改现有网站时保留 `id`，并保留仍然需要的字段；为另一个网站制作规则时，要换成新的 `id`、名称和域名。不同 `id` 的规则可能同时生效。

如果已经有自己的规则，修改前可以点击 **导出已保存规则** 留一份备份。导出不包含未保存的草稿；草稿中有想保留的修改时，先保存或复制到本地文本文件。再次复制同一条内置规则会替换草稿中相同 `id` 的内容，可用 **撤销草稿替换** 退回这次替换前的文本。

## 找到正文的 CSS 选择器

CSS 选择器是一段定位页面元素的文字。例如 `article p` 表示文章区域里的段落，`.article-body p` 表示 `class="article-body"` 区域里的段落。

下面以 Chrome 的开发者工具为例，其他浏览器的菜单名称可能略有不同：

1. 打开出现漏译的网页，在一段**原文**上右键，选择 **检查（Inspect）**。开发者工具会打开 **元素（Elements）** 面板，并选中对应的页面节点。
2. 如果选中的是段落内部的链接或加粗文字，向上查看它所属的 `<p>`，再查看包含正文的 `<article>`、`<main>` 或带稳定类名的区域。例如看到 `<div class="article-body">` 中有多个 `<p>`，可以先尝试 `.article-body p`。
3. 点击元素面板，使键盘焦点位于其中，按 Windows/Linux 的 `Ctrl + F` 或 macOS 的 `Command + F`，在搜索框中输入选择器。逐个查看匹配结果，确认它们是正文段落，没有包含侧栏、作者简介或评论操作按钮。
4. 如果范围过大，增加一个稳定的外层范围，例如 `article .article-body p`；如果没有结果，回到实际节点检查标签和类名拼写。可以分别搜索 `article h1`、`.article-body h2`，寻找标题。
5. 打开同一网站的另一篇文章，重复检查。能覆盖多篇文章且保持正文范围的选择器，才适合放进规则。

开发者工具的检查和 CSS 搜索操作可参阅 [Chrome 官方 DOM 教程](https://developer.chrome.com/docs/devtools/dom/#search-for-nodes)。这里是在读取网页结构；在开发者工具中临时修改页面，不会替你保存 FluentRead 规则。

优先使用有含义的标签、类名和属性，例如 `article p`、`.article-body p`、`[data-content="article"] p`。自动生成的长类名、很长的父子路径，以及 `:nth-child(3)` 这样的序号容易随网页改版或内容插入失效。也不要直接选整个 `body` 或把整篇文章当作一个段落。

## 添加自己的规则

下例假设你已经确认：网站的文章位于 `https://example.com/articles/` 下，标题是 `article h1`，正文位于 `.article-body`，作者信息使用 `.author-info`。这些只是示例名称，使用时换成你在网页上确认的域名、路径和选择器。

没有其他自定义规则时，可把下面这份**完整 JSON** 粘贴到 **JSON 编辑草稿**。已有规则时，可先点击 **插入示例**，在它加入的规则上修改；或将下面 `rules` 中的对象加入现有 `rules` 数组，保留其他规则并使用唯一的 `id`。

```json
{
  "version": 1,
  "rules": [
    {
      "id": "my-reading-site",
      "name": "我的阅读网站",
      "match": {
        "hosts": ["example.com"],
        "paths": ["/articles/*"],
        "excludePaths": ["/articles/editor/*"]
      },
      "mode": "focus",
      "content": [
        {
          "css": [
            "article h1",
            "article .article-body h2",
            "article .article-body p",
            "article .article-body li"
          ],
          "resolve": "closest"
        }
      ],
      "protect": ["pre", "code", "button", ".author-info"],
      "exclude": ["nav", ".advertisement"]
    }
  ]
}
```

这条规则仅匹配 `example.com` 的 `/articles/*` 路径，并排除 `/articles/editor/*`。域名里不写 `https://`、端口或路径；如实际网址使用 `www.example.com`，就填写该域名。确实需要根域和所有子域时，可使用 `*.example.com`。路径不包含查询参数或 `#` 后的片段。

`focus` 表示只接受 `content` 明确选中的正文目标。这个例子逐个选择标题、段落和列表项，并用 `protect` 保留代码、按钮和作者信息，用 `exclude` 排除导航和广告子树。若只想补充通用识别遗漏的内容，可把 `mode` 改为 `augment`；这时其他被通用识别选中的正文仍可能翻译。

初次编写规则通常不用设置 `atomic`。它默认为 `true`，每个匹配区域作为一个候选。若需要使用 `atomic: false` 的容器，仍应明确声明内部段落等选择器，尤其是在 `focus` 模式下；仅加上 `false` 不会自动把所有后代都变成正文。

## 保存，并在真实网页上验证

1. 点击 **保存规则**。出现错误时，按提示的字段路径修改；例如 `$.rules[0].match.hosts[0]` 指第一条规则中的第一个域名。
2. 保存成功后，在 **网址匹配预览 → 输入完整网址** 中填写文章地址，例如 `https://example.com/articles/first-post`，确认规则显示为 **自定义 · 已启用**。再试一个应排除的地址，确认该规则不再命中。
3. 回到实际网页，重新触发悬浮翻译和全文翻译。检查目标段落是否出现一份译文，代码、作者信息和控件是否保持原文。
4. 执行一次“翻译 → 恢复原文 → 再次翻译”。如果网站会加载更多内容或在站内切换文章，再检查这些场景。

**网址匹配预览只使用已保存的规则检查 URL，不会打开网页，也不会验证选择器是否命中真实正文。** JSON 保存成功只说明格式和选择器语法通过校验；实际范围需要按上面的步骤在网页上确认。

保存的规则会同步到已打开的网页，正在进行的翻译会取消并恢复原文。重新触发翻译后才会按新范围生成译文。保存失败时，草稿会保留，按页面提示重试即可。

## 导入、导出与恢复

**导入文件：** 点击 **导入 JSON**，选择本地 `.json` 文件。文件内容会替换整个编辑草稿，先检查再点 **保存规则**；导入不会自动合并文件与现有自定义规则。需要保留两份规则时，将它们整理到同一个 `rules` 数组中，并避免重复 `id`。若文件包含 `profiles` 模板，也要保留规则引用的模板；同名模板内容不同时，需要改名并同步修改对应规则的 `profile`。模板用法见[网站适配参考](/config/site-adaptation#复用结构模板)。

**导出文件：** **导出已保存规则** 下载当前已保存的自定义规则包；**导出内置规则** 下载当前版本的完整内置包。这两种导出都不包含翻译服务配置或密钥，也不包含启用开关、停用列表和未保存的草稿。日常备份自己的修改时，使用前者即可。

**放弃未保存的修改：** 点击 **恢复已保存草稿**，编辑框会回到最近保存的版本。**撤销草稿替换** 只撤销最近一次草稿替换，不是已保存配置的版本历史。

**恢复某个网站的内置规则：** 从草稿的 `rules` 数组中删除该网站相同 `id` 的自定义对象，注意相邻对象之间的逗号，然后保存。若此前停用了该 ID，还要在内置列表中重新打开它的开关；停用开关同时作用于同 ID 的自定义替代项。保留自定义替代项期间，该 ID 后续的内置更新不会覆盖你的修改。

**清除所有自定义规则：** 点击 **清空自定义草稿**，再点击 **保存规则**。这会清除全部自定义规则与模板；内置规则仍按原有开关状态生效。保存前可用 **撤销草稿替换** 退回，保存后需要导入自己的备份才能恢复已清除的自定义内容。

## 常见问题

- **提示 JSON 格式错误：** 使用英文双引号，检查括号和逗号；JSON 不接受注释或最后一项后多余的逗号。规则包也不接受任意新增字段，格式以[网站适配参考](/config/site-adaptation)为准。
- **预览没有命中：** 先确认已经保存，再核对完整网址、实际子域、路径大小写和排除路径。`example.com` 不会自动匹配 `www.example.com`。关闭网站适配或停用对应 ID 时，预览会显示停用状态。
- **预览命中，但正文仍漏译：** 到网页的开发者工具中检查选择器是否有结果，并检查 `focus` 是否遗漏标题或段落。网址预览无法验证页面结构；若正文位于图片、Canvas、关闭的 Shadow DOM 或尚未接入的跨域 frame 中，也不能只靠增加 CSS 选择器解决。
- **翻译范围过大，或者多个段落合并：** 把整篇文章或整块面板的选择器收窄为内部段落、标题和列表项。需要保留的元信息可加入 `protect`，整块不需要扫描的区域可加入 `exclude`。
- **修改后仍受到别的规则限制：** 同时命中的不同 ID 会共同生效；所有保护区域合并，任一 `focus` 都会收紧通用识别。提高 `priority` 不能绕开这些限制，应检查并修改、替换或停用造成限制的规则。
- **计数器仍被翻译：** `watchIgnore` 只忽略区域的动态变化，不会让文字保持原文；需要保持原文时使用 `protect` 或 `exclude`。
- **保存或读取文件失败：** 保存失败时不要关闭尚未保留的草稿，重试保存；文件过大时只保留需要的规则，单个规则包上限为 2 MB。若读取文件期间继续编辑过草稿，界面会提示重新导入，避免覆盖较新的输入。

网站适配不是扩展总开关。关闭它会回到通用正文识别；如果要让扩展完全停止在某个网站运行，请使用网站规则中的禁用设置。输入框、代码和明确禁止翻译的内容仍受底层保护。

## 把好用的规则分享给社区

规则保存在你的扩展配置中，点击保存不会自动发布。验证效果后，可导出已保存的规则，再从文件中整理出准备分享的规则；如它引用了 `profiles`，也要保留所需模板。

分享时附上可公开访问的示例网址、想翻译的正文区域、应保持原文的区域、浏览器及扩展版本，以及已完成的翻译和恢复检查。截图或示例中去掉账号信息、私有页面地址和个人内容。

无需先掌握项目代码，也可以提交规则文件和复现说明，供维护者讨论。希望把规则纳入内置目录，或为现有规则提交修改时，请继续阅读[贡献网站适配规则](/contributing/site-adaptation)。完整字段、模板合并和能力边界见[网站适配参考](/config/site-adaptation)。
