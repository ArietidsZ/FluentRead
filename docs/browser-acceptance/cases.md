# 固定源码验收矩阵

每个编号必须在结果中出现一次。下列“通过”均要求截图及可复核日志；源码阅读、单元测试和旧报告只能提供预期，不能替代真实浏览器证据。真实模型项按本次完整 GPU 验收的授权顺序执行，先满足空间与固定资源校验前提。UI 标签以实际页面为准。

## 无模型下载的浏览器夹具

- **ENV-01**：验证 BrowserOS Neo 实际能力、版本、临时 profile、扩展身份、窗口/焦点保护和 OS/浏览器 GPU 诊断。正常/无痕上下文不能误接到别的扩展或日常 profile。缺必要能力即阻断相关项。
- **UI-01**：用首页合成段落和现有 Popup 专项，检查供应商实际选择与匹配模型、全局继承与功能专用分配、空搜索、凭据提示、返回/重开保存、390px 与深色界面。全文“翻译→恢复→再翻译”各次只产生预期请求，恢复后源 DOM 不变。真实 API 可用性不属于此项。
- **PRIVATE-01**：同一临时 profile 开正常与无痕窗口，开启无痕专用服务/模型；普通 `fixture-normal` 与专用 `fixture-private` 使用同一合成段落。并发单条、批量、页面摘要与功能专用覆盖都必须路由到正确模型；普通高级请求体的 model 不能覆盖专用模型。专用配置缺失/无效时明确失败且普通端点计数不增。正常窗口配置不变；UI 开关关闭后行为符合默认配置。参考 `tests/privateTranslation.test.ts`、`privateTranslationPreflight.test.ts`、`privateTranslationSettings.test.ts`。
- **PRIVATE-02**：先在正常窗口制造缓存命中和用量基线，再用相同文本/相同模型在无痕窗口请求。观察真实发送者与无痕上下文：不得读取/写入共享翻译缓存、请求记录或 token 用量，不得和普通窗口合并在途请求或摘要。关闭全部无痕窗口后重开，普通缓存/统计保持原有值，私密哨兵不出现于持久存储；伪造网页消息的 incognito 字段不能触发专用路由。仅用合成内容，脱敏结果不要导出整个存储。参考 `tests/privateTranslationIsolation.test.ts`。
- **YT-01**：复用 `run-youtube-subtitle-sync-test.cjs` 的现有 DOM、JSON3 cue 和真实视频时间，核对整句/逐词字幕、可靠边界、重复句、延迟翻译、空档、seek、暂停、全屏、偏移、原文模式和关闭清理。JSON3 不可靠偏移保留整条，XML 不猜测边界。记录这是假 YouTube 页面/固定翻译，不能写成在线或 ASR 通过。
- **OCR-UI-01**：普通单图明确选择 PaddleOCR，“仅选择”不下载模型；立即关设置后重开仍保存。关闭漫画时只显示共享 OCR 资源，不显示无关 LaMa；普通单图继续使用轻量交互，不强行进入连续漫画模式。覆盖窄屏、英语/中文、深色；此项不证明 OCR 推理。

## 可选择的真实模型与在线页面

- **YT-02**：在用户允许的公开、非受保护 YouTube 测试视频上，先保留原生字幕优先，再显式开启当前实际 GPU ASR 模型。首次模型准备、音频捕获和真实推理成功；按实际版本分别记录模型，不将 Whisper、Qwen 或替身互换。确认没有 CPU 结果冒充 GPU。网页/模型网络不可达即阻断，不登录私人账号。
- **YT-03**：对 YT-02 的一次新完成输出记录 arrival/显示/清除时钟。完成时开始显示 **1800 ms**，重复 cue 不续命，过期历史 cue 不复活；相同文字的新 cue 可显示，较旧纠正不能覆盖新 cue。保存原始 `startMs`、`spokenEndMs`、`availableAtMs` 和导出 SRT；展示期限不能重写历史音频时间。真实时钟采样须注明容差和原因，目标值仍是 1800 ms。不能把推理总时延说成 1800 ms。参考 `youtubeLocalRuntime`、`youtubeLocalCaptureLifecycle`。
- **YT-04**：真实推理期间暂停/恢复、前后 seek、SPA 切视频、关闭字幕、卸载/重开与重复点击；旧识别和译文不能回写新页面，旧音轨/监听器/Worker 释放，取消后能明确重试。原生轨道更新在本地主动模式中不抢占；停止/失败时恢复原生字幕优先。静音按钮和捕获 track 的 `muted` 不是同一概念，分别记录。
- **YT-05**：独立负向夹具触发受保护媒体和不可访问/初始 muted 音轨、运行中 track mute。必须明确拒绝/停止识别、清理资源、保留或恢复原生字幕；不能绕过 DRM 或抓取受保护媒体。若使用测试替身，明确记录注入点，不能称为实际 DRM 视频测试。参考 `tests/youtubeLocalCaptureLifecycle.test.ts`。
- **OCR-01**：在首页合成普通图片上，用生产扩展明确选择单图 Paddle，真实固定检测/识别模型在物理 GPU 执行，识别关键全文且显示译图；翻译可用本地固定端点，必须标注。没有 Tesseract 语言包时仍成功；不加载 LaMa、不隐式改为 Tesseract/WASM，恢复原图、重试和缓存复显可用。保存实际输入 PNG 及输出截图。
- **OCR-02**：同一组可再现漫画图走生产 Paddle + LaMa。实际按需修补、译字可读、原图/译图切换、取消/恢复、动态换图、滚动返页无迟到覆盖。记录 OCR/修补/文字翻译分别用什么后端及输出；LaMa 真实执行需日志/dispatch，简单白底若没有触发 LaMa 不能算通过。可使用已有漫画脚本和合法自有复杂背景样图，固定其 SHA-256。
- **OCR-03**：独立故障注入使 GPU 不可用、初始化失败、设备丢失及识别库吞错边界出现；错误必须传到 UI，全部已建会话清理、可重试，不报告成功的空 OCR，也不自动重建 CPU 会话。使用当前生产路径；记录注入代码差异。参考 `tests/mangaGpu.test.ts`。
- **TTS-01**：实际设置中的默认 GPU 执行模式保存/重开，并从内容朗读或试音入口一直传到生产 owner/Worker。真实 Kokoro 输出可播放、非静音、语种/声音/速度正确；同时记录首次与重复播放。只有显式选择兼容模式才能另测其回退，不能替代默认 GPU 通过。参考 `localTtsSettingsExecution`、`localTtsExecutionWiring`。
- **TTS-02**：使用首页长中文、日期、数字和英文结尾哨兵，真实 Kokoro 原生 tokenizer 运行，不替换 tokenizer。含特殊 token 的每个最终片段不超过 512；完整音频能听见结尾，没有静默截断、重排或丢失数字。不可拆分超长词/数字应明确失败；不要以合成前文本或 WAV 非空替代末尾听检。保存合成测试文本、片段计数/顺序和非个人音频的哈希。
- **TTS-03**：播放/合成中取消、立刻新请求、关闭/重开；旧音频、迟到结果和旧 owner 不能覆盖新请求。改 GPU/兼容模式应使旧会话按契约结束。记录可重试及资源释放。参考 `localTtsLifecycle`、`localTtsExecutionWiring`。
- **TTS-04**：固定 revision 全量 SHA 校验缓存后，重启本次扩展并阻断模型网络，重新真实生成，确认所有执行上下文零模型下载。下载中清缓存应拒绝，清理中下载也应拒绝，清理失败不能留下假“离线可用”，清理只影响该模型的登记文件。兼容历史别名不产生额外 main 副本；损坏/缺文件必须拒绝。参考 `localTtsModelCache`、`localTtsCachePolicy`。
- **TTS-05**：在默认 GPU 模式下注入缺 GPU、初始化失败、运行中 device-loss；必须显式失败、释放会话且不隐式重建 CPU。为显式兼容模式另记真实后端和结果，不与默认模式合并。旧 audio GPU runner 的 WASM 默认预期不能用于本项。
- **MT-01**：逐个真实测试固定目录的严格 GPU 配置：OPUS 中→英及英→中 FP16、日→英 FP32，以及 Index 中→英及英→中。记录物理 GPU、原始 features/limits、dtype、模型/运行时哈希、显存/时延和正常句子的完整输出。FP16 与 Index 必须真有 shader-f16；模型准备前 admission 失败应明确拒绝且不下载无用权重。每个模型/方向缺证据都使本项 blocked，不能让一个模型代表全目录。
- **MT-02**：逐个 GPU profile 独立注入不满足能力/初始化失败/device-loss；错误有界结束，旧设备/Worker 清理，没有 CPU 重建或别的模型悄悄替代。注入时不能把软件 adapter 改成“物理 GPU”。参考 `tests/localTranslationWorkerCommon.test.ts`、`tests/opusTranslationWorker.test.ts`、`tests/indexTranslationWorker.test.ts`。
- **MT-03**：真实长请求中取消、立即新请求、切换 GPU 模型及普通/无痕专用 profile；旧 owner 的完成/错误不串到新请求，取消后的缓存/用量不误记，重复切换可恢复。至少在两个实际模型间执行，记录模型和请求边界。对单图、字幕或 TTS 切换不能代替 MT 验收。
- **MT-04**：从产品支持入口准备固定 revision、全部预期文件尺寸/SHA 验证后，关闭再打开该测试扩展；阻断所有实际模型源，在所有执行上下文观察零请求，重新真实推理成功。缺文件/损坏缓存必须显式拒绝且不偷偷连网或退回 CPU；只对本次临时模型缓存做负向测试。准备成功或 UI“已缓存”单独不足以通过。

## 证据解释

`YT-05`、`OCR-03`、`TTS-05`、`MT-02` 是负向故障注入项。其余项如果需要额外替身，只能补充观察，不能将真实模型项改名为夹具通过。对线上字幕、浏览器音轨限制、硬件兼容性和模型质量作结论时，应指出本机/本浏览器/本模型/本视频的边界。
