# X AI 字幕：音频可靠性与字幕预览修复验证

日期：2026-10-09。对照基线：`origin/main` 的 `9ce9d7b5b`。本轮修复音频恢复和识别状态问题，并建立真实 Whisper 对照；识别文字的准确率仍需要真实视频语料继续优化。

## 已修复的行为

- 模型检查或下载期间，同一视频补全海报和媒体 ID 仍能启动识别。真正换视频、切换源语言、关闭翻译或卸载后，迟到的请求仍会作废。
- 从 X 页面已加载的视频元数据中提取有界的媒体 URL 和码率，按当前视频媒体 ID 配对。主清单和音轨失败后尝试备用音轨与低码率完整 MP4；限制候选、读取字节、时长、请求和解码等待。
- XHR 的二进制小型清单可旁路解析；Fetch 副本按流限制大小，取消副本不会取消页面的原响应。
- 完整识别逐窗展示稳定句并翻译当前播放位置附近的字幕。全片成功后才写入完整缓存或导出 SRT；后窗失败清除预览并保留重试入口。
- 读取和识别展示实际进度；保留短句尾音，跳过数字静音。裁剪长静音边缘后恢复原时间偏移，保持原窗口的解码 token 预算。

## 真实识别结论

使用同 SHA 的三条 macOS 合成普通话，在生产 Whisper Worker 上比较 Tiny 和 Base，分别显式指定中文与自动语言。修复前后两种模型的输出文本逐字相同；本轮没有证据支持字词准确率提升。

| 样本 | Tiny 原始 CER | Base 原始 CER |
| --- | --- | --- |
| 3.48 秒短句 | 20.00% | 33.33% |
| 5.86 秒字幕测试句 | 46.15% | 3.85% |
| 9.22 秒连续对白 | 36.54% | 28.85% |

CER 去掉标点和空白，但把简繁差异算作错误。它不能直接当作纯语音内容错字率。仍有真实内容错误，例如 Tiny 把“识别”输出成“10別”，Base 把它输出成“实别”；Base 在古文短句上也更差。三个合成样本不足以确定整体最佳模型，默认模型没有调整。

6 秒数字静音首次请求在约 83–85 ms 返回空文字与空字幕，`inferenceMs = 0`，没有初始化识别模型。其收益限于数字静音门控，不能推断整段视频的速度或语义人声检测效果。模型下载/缓存、冷启动和热推理分开记录；浏览器汇总 RSS 包含浏览器各进程，不能当作扩展独占内存。

另外已准备固定 q4 encoder、仅切换 q4/q8 decoder 的受控实验及约 84.4 MB 公开权重。唯一一次纯 Worker 运行在浏览器启动阶段超时，尚未进入模型；没有精度、速度或内存结论。固定文件摘要、参数、原始失败与复跑位置见 [准确率实验准备记录](./accuracy-experiment.md)。

## 验收边界与后续工作

生产浏览器夹具使用真实 MSE/HLS/MP4/AAC 与 PCM 解码，ASR 和翻译响应受控；它们验证采集、媒体隔离和交互，不能证明真实模型在 X 音频中的准确率。真实 Worker 对照使用合成普通话，尚未覆盖真人口音、背景音乐、多人、英语及其他语言。

当前没有用户本次失败视频的链接，无法确认那些视频已恢复。部分追加浏览器运行因隔离启动层无法取得 DevTools 端口而停止，尚未开始产品断言；失败运行不会计入通过结果。Firefox 已构建并检查 manifest，尚未进行 Firefox 实机音频验证。

下一阶段应固定用户失败视频的授权音频或可公开访问链接与正确转写，按语言、背景音乐、短句和连续对白建立语料。先分别测量音频取得率、完整字幕成功率、错字/漏句和首句等待，再决定模型、解码精度或语义 VAD 调整。[开源实现审查](./open-source-review.md)记录 yt-dlp、Whisper Web 和 WhisperLiveKit 的可借鉴设计；本轮为 FluentRead 独立实现，没有复制其代码或添加运行时服务依赖。
