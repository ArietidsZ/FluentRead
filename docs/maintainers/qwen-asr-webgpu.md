# Qwen3-ASR 0.6B WebGPU

新增可选模型 `qwen3-asr-0.6b`，不改变已保存的 Whisper 选项。它使用独立 Worker 和直接 ONNX Runtime WebGPU 适配器，不把 Qwen 交给 Transformers.js 3.8.1 的 Whisper pipeline。未实现 CPU 推理；GPU 不可用或执行失败会返回错误，后续重试创建新 Worker。

## 模型与运行时

- 权重：[jiangzhuo9357/Qwen3-ASR-0.6B-ONNX](https://huggingface.co/jiangzhuo9357/Qwen3-ASR-0.6B-ONNX/tree/4a01b95fafe2c9e3af77e33c18bbb7de349c62f6)，固定 revision、每个文件的大小和 SHA-256，模型 Apache-2.0
- 有 `shader-f16` 选择 q4f16，其他支持 WebGPU 的设备选择 q4。约889MB/1.30GB为下载量，不是运行内存
- 直接 ORT 别名固定1.26.0-dev.20260416-b7804b056c，与已有 Kokoro 包的运行时一致；复用匹配的静态 WASM 文件，不下载执行代码。旧 Whisper 的 ORT 版本不变
- SDK只用其公开接口；没有复制 AGPL 参考应用实现
- 下载复用已有4MiB分块、Range续传、哈希校验和离线Blob读取，按当前变体准备数据，不同时下载两套权重。下载只发生在显式模型准备操作中；识别 Worker 纯离线读取，缺失或损坏时要求重新下载，不在转写过程中隐式下载另一套权重

## 推理与时序

固定128维Slaney滤波器配合现有原生音频特征提取器，400点周期Hann、160步长、反射填充、最后一帧截去及log-Mel归一化。传入实际音频长度，不填充为30秒。

嵌入矩阵保留INT8和逐行比例，仅展开当前token行。编码器输出拼接到提示词嵌入；预填充和增量解码共享下载的数据，分别创建GPU会话。KV缓存保留在GPU，每步释放旧张量。输出为最后位置的logits，贪心选择，遇EOS结束；超出256token报告失败，不把截断文本当作完成。

字幕只有音频窗口边界，结果明确标注 `timestampSource: window`。本导出没有词级强制对齐。近数字静音和不足400采样的输入在模型加载前跳过；这不是语音活动检测器，不承诺过滤音乐或环境噪声。

## 已运行的检查

- 六组独立NumPy FFT参考：静音、脉冲、正弦、chirp、固定随机噪声和短边界。所有128个频率通道与原生JS前端误差不超过2e-5
- 单元测试覆盖精度选择、嵌入、EOS、未知语言、长度上限、无效数据、设备丢失、部分初始化清理、并发拒绝、取消、Worker切换与重试、缓存选择
- 实际软件WebGPU：3.38秒英文句子逐字匹配；4.20秒AISHELL普通话13个参考字符全部保留，模型添加句号。两个片段均到达EOS，KV位于GPU，释放后计数的GPUBuffer归零
- ORT分区检查：编码器489个GPU节点/31个主机节点，解码init1503/22、step1574/13。主机节点仅依赖形状、位置和常量，包括因果mask；不依赖音频、嵌入、KV内容或学习权重

以上实测使用Node Dawn/SwiftShader，不是浏览器扩展验收，也不是物理GPU性能。软件环境单片段约148秒，进程峰值约4.73GiB、API请求GPUBuffer峰值约1.72GiB。首次一次运行被环境终止，原因没有确认；减少验证脚本中的复制并暂停并发重检查后，完整两片段通过。不能因此断言任意长音频、低内存设备或多个模型同时运行都安全。

自动语言和未知语言代码在英文、普通话共四个实际软件GPU用例中均到达EOS；结果与固定语言版本相同。q4f16随后在真实Lavapipe软件适配器上通过英文、普通话用例。仍需验证实际浏览器生命周期、硬件GPU、噪声/专名/数字/混合语种和更长音频。两段语音不构成模型排名，不能证明该模型全面优于现有Tiny/Base的质量、延迟、内存或下载量。

参考：原生WebGPU[会话选项](https://onnxruntime.ai/docs/api/js/interfaces/InferenceSession.SessionOptions.html)、[GPU张量生命周期](https://onnxruntime.ai/docs/tutorials/web/ep-webgpu.html)、[Qwen官方预处理配置](https://huggingface.co/Qwen/Qwen3-ASR-0.6B/blob/main/preprocessor_config.json)。

## 删除实验

删除专用Worker中每token额外的`setTimeout(0)`后，推理、取消、错误重试的29项定向测试仍通过。GPU运行本身已异步等待，额外timer不参与模型计算。独立Node调度对照中，64次迭代的五次采样为有timer约69.7–73.7ms、无timer约0.012–0.017ms；这只测人为调度开销，不是GPU模型加速比。实现保留无额外timer版本。

没有新增FFT实现：原生特征提取器通过全部独立数值参考，固定30秒填充与模型的真实长度契约不符。没有新增模型文件数据库：原有分块仓库抽至平台层，相关缓存与探测的48项定向回归通过。INT8嵌入表保持原布局，仅构造当前行与有界prompt，避免先把整个词表展开为FP32。

生产转写owner的32秒预算保持不变，首次未预热时也包含加载；独立预热预算为120秒。上述约148秒的软件测试不包含下载和会话初始化，只证明模型核心。它没有通过生产owner时限，不能作为实时字幕响应速度或完整浏览器流程的验收。软件全流程验证需要明确的测试专用超时扩展，不能据此延长生产时限。

终止性错误或超时会释放对应流的所有权，另一个标签页无需手动取消旧流就能继续；迟到的旧Worker响应不能清除新流。Qwen不保留从未使用的CPU重试PCM副本，每个30秒请求最多避免约1.92MB额外复制。


## 内存方案对照

使用相同英文、普通话片段的软件WebGPU对照：

| 运行时/缓存 | API GPUBuffer峰值（字节） | 进程RSS峰值（KiB） |
| --- | ---: | ---: |
| 当前1.26 | 1,841,885,120 | 5,027,496 |
| 1.30 bucket | 1,722,347,616 | 5,025,672 |
| 1.30 lazyRelease | 1,574,311,200 | 4,927,624 |

所有结果文字一致，最终受跟踪缓冲区均释放。1.30中lazyRelease相对bucket降低8.6%缓冲区峰值，但分配次数从4,004升至15,947。单次软件测量没有证明速度更快；1.26运行还包含额外英文重试，不能当作完全匹配的时间基准。为Qwen单独引入1.30会增加约26.8MB原始运行时文件（约6.6MB gzip），而当前版本复用已打包的Kokoro运行时。因此暂不增加第二套运行时。

[ORT Web会话选项](https://onnxruntime.ai/docs/api/js/interfaces/InferenceSession.SessionOptions.html)提供externalData，没有公开共享initializer或prepacked-weight容器接口。复用同一下载字节不等于两个原生会话共享GPU权重。当前q4/q4f16解码权重分别为382,035,968/344,670,208字节，会话内分配须以实测为准。

已检查真实[合并解码器导出](https://huggingface.co/goryodog/tokihisu-qwen3-asr-0.6b-webgpu/tree/62493632e19acdf7b4a5733a2d4a032cf1abce90)：FP16解码权重1,503,250,432字节，编码器372,749,504字节。其800帧填充、独立KV输入和种子mask契约不同；清单没有量化合并变体。单个FP16解码权重已超过当前两个量化权重文件之和，不能仅因会话数减少就声称更省内存。本次没有编写未验证的ONNX图合并器。

真实owner验证使用测试专用延长时限通过短英文；原生产32秒时限也实际触发，随后另一stream通过隔离子进程传输恢复。Node worker_threads在终止未完成mapAsync时出现Dawn进程断言，改用子进程只隔离验证环境故障，不代表浏览器层已验证或已发现同类浏览器故障。


## shader-f16 实测

在同一Lavapipe软件适配器、相同英文片段下：q4f16的API GPUBuffer峰值为1,147,870,800字节、进程RSS峰值3,265,968KiB；q4分别为1,682,173,760字节和4,383,868KiB，下降31.8%和25.5%。英文文本相同，q4f16普通话也保留全部参考字符并添加句号。单次运行耗时25.25/26.65秒，仅作记录，不构成速度排名。

Lavapipe上的短英文真实owner调用在未修改的32秒生产时限内完成，用时12.10秒，返回`Hello world.`及0–1235ms窗口。该验证仍通过Node子进程传输，不是浏览器扩展验收；不能把一个短片段外推为任意长窗口的实时保证。实际q4f16内存收益支持现有按shader-f16自动选择变体的实现，无需新增运行时或CPU路径。


## 空终止文本回归（2026-10-04）

固定留出集仍保留原始结果：两个无语音诊断夹具 `noise-2s` 与 `noise-tone-2s` 在原始 worker 中失败。独立补充重放通过只记录、不改变返回或抛出行为的测试插桩，实际捕获到原生 Tokenizer 收到零个文本 token，并在 `decode([])` 处抛出异常。该证据不能用于解释其他数字或语义错误。

修复只在成功 EOS 后得到空文本 token 时直接返回空字符串；正常 token 仍走原生解码，解码异常及清理语义不变。Node 22 的 `pnpm exec vitest run tests/qwenAsrEngine.test.ts` 共 23 项通过；删除这一空值判断后，即时 EOS 和控制标记后 EOS 两项失败，恢复判断后 23 项再次通过。

实际软件 GPU 补充重放中，两份原始噪声输入均得到成功的空文本和空字幕段；随后同一 worker 的固定英文语音转写与修复前逐字一致。最后显式 dispose 后跟踪 GPU buffer 字节为零，子进程退出。该三例检查独立于原始留出集，没有替换其失败记录，也不构成浏览器、物理 GPU 或通用识别质量验收。软件适配器准入与文件缓存适配均为明确的测试配置。
