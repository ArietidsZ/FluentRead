# 漫画透明镂空的完整译文排版

Issue #1068。基线为 `759608d6`，包含 #1104 的共享分词与候选搜索优化。本次处理透明镂空把段落切成多个可用区间后，连续矩形排版需要缩小文字的问题。

受影响的短段先使用原文字框可容纳的完整行和字号，把完整词、字素及东亚标点依次放入同一行的无孔区间。开引号、句末符号旁的原有空白仍保留，标点随相邻文字跨孔移动。原行、字号和基线保持不变，不横向压缩文字。

度量仅用于提出计划。每个计划绘入带 8 像素整数保护边的局部透明画布，检查实际非零 alpha 像素单元与原框、全部保护孔是否相交，再逐通道比较同一位图裁切前后的 RGBA。任何非零 alpha，包括 1 和 2，都属于笔画。只有真实像素不安全才允许增加一次固定 1 像素水平余量；不支持的文字、预算不足或无法完整放入时，沿用现有连续矩形排版。真实 Canvas 错误保持原异常，由现有调用链保留原图。

通过审计后，以整数坐标合成同一张位图并立即释放，不重新绘制字体。清字与最终绘字继续共用原图冻结的保护区。普通无孔图片不创建这些字形画布。

## 资源边界

每页最多 64 段进入额外路径，每段至多 h0/h1 两个计划。纯算法仍限制 4,096 个 UTF-16 单元、256 个 token、16 行、32 个行内区间、1,024 次度量及 65,536 次投影比较。

局部画布最大 2MP、边长 8,192；每次尝试两张画布及两次已有 RGBA 读回。整页共用累计 16MP 画布、16MP 读回与 16MP 审计预算，以及约 8M 次像素与孔比较。活动画布和读回另有上限；释放不返还累计额度，重排和下一区域不能重置账本。这些是额外路径的名义预算，不能代表整个浏览器的 RSS。

实际两个 dock 段落使用 18,832 和 16,297 像素的局部层，合计四张画布、四次读回，各计 70,258 像素。正常产品路径没有实验用的 PNG 编码。带观察器和 PNG 导出的时间不能作为产品速度对照。

## 证据范围

这是当前产品源码的原生 Canvas 排版验证；没有调用 OCR、LaMa 或真实翻译服务，也不是完整扩展页面、移动设备、语言准确率或竞争项目的性能验收。保护像素与同一浏览器解码的原图比较，不把原始 PNG 通道值与浏览器的 alpha 量化混为一谈。固定保护边是当前用例验证范围，不是所有字体实际外延的普遍定理。
